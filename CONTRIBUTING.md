# Contributing to the R mailing list archives

Thanks for your interest. This organization mirrors the public archives of the R project's mailing lists. Almost every repository here is written by a scheduled job rather than by hand, so a good report is usually worth more than a pull request.

## One front door

All feedback about the archives, the data, and the site is tracked in one place: [r-mailing-lists/feedback](https://github.com/r-mailing-lists/feedback/issues/new/choose). Use it to report a missing message, a garbled body, a broken thread, or a site bug, and to suggest a list we should be mirroring. Reporting there keeps everything discoverable and avoids scattering issues across thirty-odd repositories.

One thing is worth checking first. If the problem is also present in the upstream archive, which lives at a URL like [stat.ethz.ch/pipermail/r-help/](https://stat.ethz.ch/pipermail/r-help/), then it is baked into the source and we cannot fix it here. Tell us either way. Whether upstream agrees with us is the single most useful thing a report can include.

## Pull requests

Focused pull requests are welcome on the repository they affect. Please do not send pull requests that edit archived message content: those repositories are regenerated from upstream, so the change would be overwritten on the next run. For anything larger than a small fix, open a report at [r-mailing-lists/feedback](https://github.com/r-mailing-lists/feedback/issues/new/choose) first, so we can talk it through before you spend time on it.

## Removal requests

Requests to remove a message or personal information do not go through the issue tracker. See the [archive policy](https://github.com/r-mailing-lists/.github/blob/main/ARCHIVE_POLICY.md).

## Code of conduct

Participation is covered by our [Code of Conduct](https://github.com/r-mailing-lists/.github/blob/main/CODE_OF_CONDUCT.md).
